## 1. What was audited (and found)

Method: code read + live browser verification (Playwright against a real
server), not UI-label assumptions.

### 1.1 Duplicated / unnecessary controls on the Create screen — found and removed

| Finding | Where | Why it was unnecessary |
|---|---|---|
| **Build agent dropdown** | `#yt-agent-btn` + `#yt-agent-menu` in the YouTube topbar (`index.html`) | Duplicated the shared Build-agent selector that already exists in the Ads Studio header and the Activity console (one shared state: `dennis.studio.agent`). It was never consulted by `submitCreate()`. Spec default is stated, not chosen, on Create: "Agent: OpenCode". |
| **"New Video Project" (topbar)** | `#yt-new-project` (`index.html`) | Always-visible duplicate of the prompt-first creation path. Spec §20: Create = prompt composer + Create button. Four buttons ("yt-create-video", "yt-new-project", "yt-overview-create", "yt-projects-create") all opened the same blank-project modal — reduced to the one contextual action on the Projects page (until Phase 7 auto-transfers approved packages). |
| **"New Blank Project" (hero)** | `#yt-create-video` (`index.html`) | Same duplicate; the composer *is* the creation entry point ("MoraViral-inspired, prompt-first"). |
| **"New Blank Project" (empty state)** | `#yt-overview-create` (`index.html`) | Same duplicate; empty-state copy now points to the composer. |
| **Build agent dropdown (shared header)** | `.studio-buildagent` in the shared Studio header | Ads-only tooling (runs Studio generation tools). Hidden while the YouTube workspace is active — YouTube has no agent to run; script generation uses the server-side OpenCode profile from Settings. |
| **Ads voiceover strip** | `#ads-voiceover` above the shell | Duplicated YouTube Settings → Voice (`#yt-voiceover`, same TTS registry). Hidden while YouTube is active. |
| **Ads status pill / refresh / settings** | `#studio-status`, `#studio-refresh`, `#studio-settings-btn` | Ads provider state; hidden while YouTube is active (extended the existing rule to the whole `.collart-header-right`). |

Kept (spec-required): composer, channel selector, template selector (honest
"Phase 3" disabled placeholder), format, style, aspect ratio, target duration,
Agent/Model/Voice/Audience chips (defaults display), Create button, refresh,
workspace switch, recent projects.

### 1.2 Design divergence — found and fixed

`css/studio-youtube.css` carried **two visual languages**: a zinc/Collart
layer for shell chrome and a slate/indigo layer (create composer, subtabs,
backlog cards, intelligence tiles, settings) that matched neither the Collart
shell nor the OS theme. The OS itself is the ui-ux-pro-max OLED dark skin
(`--uupm-*` tokens; dark `#0f172a` surfaces, one green `#22c55e` action
accent, sky for status only, Inter, 8/10/14/16px radius scale, 180ms motion,
visible focus). The YouTube workspace is now aligned to it end-to-end —
scoped so **Ads Studio stays on the light Collart skin, untouched**.

Two live-render defects were caught by browser inspection and fixed:

1. **Light strip under content**: `#studio-view` kept the Collart light
   background (`#f7f7f8`) and block-flow; content shorter than the viewport
   exposed it below the shell. Fixed with a YouTube-scoped flex column root +
   OLED background/foreground.
2. **Voiceover widget light island**: the shared TTS widget's own dark
   Tailwind styling is outranked inside `#studio-view` by studio-v2's
   `input/select/textarea` light rules. Scoped dark restoration + green
   action button for `#yt-voiceover` only.

## 2. What was reused (no rebuilds, no duplicate services)

- Shared workspace shell (`studioWorkspaces.js`, `studioWorkspaceState.js`)
  and hash routing (`#studio/youtube/<section>`).
- Shared Build-agent state (`studio.js` `renderAgents` — only its host list
  was cleaned; `yt-agent-*` entries removed).
- Shared TTS registry widget (`voiceRegistry.js` `mountVoiceover`) — two CSS
  scopes added, zero JS changes.
- Server-side LLM profile (`backend/studio_llm.py`, OpenCode CLI →
  `nvidia/z-ai/glm-5.3-flash` default) — unchanged.
- All editorial APIs and stores (`backend/youtube_*.py`) — unchanged.
- Design tokens from `css/theme-uiuxpro.css` / MASTER.md — consumed, not
  forked.
