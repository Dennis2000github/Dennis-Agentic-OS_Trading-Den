## 1. Executive verdict

The existing Agent Skill Builder is **real, working and already has the right
safety spine**: single-fetch extraction, content cache, async jobs with
progress/cancel/dedupe, an editable draft, a hard review boundary, and
verified atomic Vault publication. That spine must be preserved.

However, it is **not yet a video reverse-engineering engine**. Today:

- "Visual extraction" is **one prose completion** from Gemini over the whole
  video. There is no scene detection, no shot list with machine timestamps, no
  representative-frame sampling, no audio-event analysis, and no normalized
  evidence object. Everything downstream consumes a single Markdown blob.
- The "skill" is **one SKILL.md** generated by **one prompt**. There is no
  package (`STYLE.md`, `FORMAT.md`, `PRODUCTION.md`, `DEPENDENCIES.md`,
  `CONFIG.yaml`, assets, scripts, tests, manifests), no strategy layer, no
  style/format separation, no production-technology reconstruction, no
  dependency resolver, and no replication test.
- **Video Reverse Engineering is hidden in the UI.** `index.html` exposes only
  `source` and `templates` modes; `setMode()` coerces everything else to
  `source`; `getObjective()` always returns `tutorial`; the character field is
  permanently hidden. The backend still supports `mode="video"` and
  `objective="reference"`, so this is a UI/regression gap, not a backend delete.
- Jobs are **in-memory only**: a restart silently loses every running job, so
  "resume interrupted jobs" is not possible today (even though
  `backend/studio_jobs.py` already contains a persistent `JobStore` pattern to
  reuse).
- There is **no Skill Registry**; `list_skills()` scans directories.

**Conclusion:** extend in place. Add a normalized evidence layer and staged
classifiers *in front of* the existing generation step, then compile a package
instead of a single file, and reuse the existing draft/publish machinery with a
backward-compatible schema. No rewrite, no new database, no new framework.

Key architectural facts:

- **No relational database.** Persistence is JSON files plus Markdown.
- **No worker queue.** `skill_jobs.JobRunner` is a thread pool inside the web
  process (`MAX_JOBS=40`, `MAX_PARALLEL=2`).
- **No separate frontend build.** Vanilla JS, no bundler; `index.html` loads
  `js/skill-builder.js?v=20261029-cursor-openclaw` at line 3999.
- **Single local owner.** `backend/auth.py::Auth` issues one token from
  `data/auth.json`; `_require_owner()` gates every Skill Builder route.
- **Provider routing is Gemini-first.** Optional CLI agents can author the
  skill (`_agent_author`), but video understanding requires Gemini.

## 7. Skill-generation and publication workflows (current)

### 7.1 Generation

`_skill_prompt()` (1502) is a **single** instruction block:
frontmatter + sections (`When to use`, `Inputs`, `Outputs`, `Tool requirements`,
`Core methods`, `Workflow`, `Decision framework`, `Failure handling`,
`Success criteria`, `Best practices`, `Pitfalls`, `Vocabulary`, `Sources`),
plus video-specific rules (reference: Acquire→Analyze→Extract→Adapt→Refine→
Generate→Compare→Iterate→Save; tutorial: method extraction only).
`_sources_block()` wraps untrusted text in
`[[UNTRUSTED SOURCE n START/END]]` and truncates visual at 16 000 chars.
Output is forced into `---\nname:…\ndescription:…\n---` by `_set_frontmatter`.

### 7.2 Review

`openReview()` renders name/description/content; `scheduleSave()` debounces;
`update_draft()` validates name regex, 10–500 char description, ≥40 char body,
≤512 KB. Autosave failures keep local edits (`state.dirty`). Reject removes
only `drafts/<id>.json`.

### 7.3 Vault publication

```
publish_draft(draft_id, fields, overwrite)
  ├─ get_draft()
  ├─ _validate_fields()                 name/desc/content/size
  ├─ vault.ensure_vault()
  ├─ rel = "Skills/<name>/SKILL.md"
  ├─ target = vault.resolve(rel)        realpath confinement
  ├─ if exists and not overwrite → 409 SkillConflictError
  ├─ _write_text_atomic()               tempfile + os.replace
  ├─ read back and compare bytes
  ├─ verify frontmatter name/description
  ├─ remove draft record
  └─ return {path, absolute_path, bytes, created/replaced, verified}
```

**Gaps in publication for a package:** only one file is written. No
`assets/`, `scripts/`, `tests/`, `manifests/`, no per-file reference
validation, no required-test gate, no version history, no skill-registry entry.

## 11. Proposed target architecture (in-place extension)

```
app.py (unchanged routing style)
  └─ backend/skill_builder.py            orchestration only (keeps public API)
       ├─ backend/skill_evidence.py       NEW  normalized evidence + timestamps
       ├─ backend/skill_media.py          NEW  ffprobe/ffmpeg probe, scene, frames
       ├─ backend/skill_analysis.py       NEW  Gemini passes → structured JSON
       ├─ backend/skill_strategy.py       NEW  reverse engineering + style/format
       ├─ backend/skill_production.py     NEW  technology + dependency resolver
       ├─ backend/skill_compiler.py       NEW  package writer (multi-file)
       ├─ backend/skill_tests.py          NEW  validation + replication harness
       ├─ backend/skill_registry.py       NEW  versioned registry + provenance
       ├─ backend/skill_sources.py        unchanged (extended with media path)
       ├─ backend/skill_jobs.py           extended: persisted snapshots + resume
       └─ backend/vault.py                reused; add package-aware validation
```

Design rules:

1. **Evidence first.** No classifier may invent data; every field carries
   `source` (`observed|transcript|metric|hypothesis`), `confidence`, `t` and
   `provenance`.
2. **Adaptive sampling.** `skill_media.plan_sampling(duration, scene_rate)`
   returns ≤ N frames (default 24 short / 8 long) and a scene threshold; costs
   are stated before execution.
3. **Cheap by default.** Text-only / no-install analysis must work with
   ffprobe + Gemini; frame extraction is opt-in per job.
4. **One generation boundary preserved.** Drafts remain drafts; publish remains
   explicit; new package files are written only during publish.
5. **Backward compatible.** Old drafts publish as before; new fields are
   additive; `content` remains authoritative for `SKILL.md`.
6. **No new runtime dependency** for the core. `ffmpeg/ffprobe` are already
   present; optional providers are detected, never installed.

## 14. Security assessment

Existing controls (keep):

- Local owner token on every route (`app.py::_require_owner`).
- URL scheme allow-list + public-host/redirect revalidation
  (`skill_sources.validate_url`, `_SafeRedirectHandler`).
- Bounded downloads/timeouts; repository content read as data only.
- Untrusted-source delimiters in prompts.
- Name regex + Vault realpath confinement + atomic write + byte verification.
- Gemini key server-side only; job snapshots never contain credentials.

New risks introduced by this upgrade and required mitigations:

| Risk | Mitigation |
|---|---|
| ffmpeg command injection via filenames | `subprocess` argv lists, no shell, fixed output dir, sanitized ids |
| Frame extraction filling disk | Cap frames (`≤24`), resolve `≤1280px`, TTL cleanup, quota check |
| Untrusted video metadata in prompts | Keep delimiters; strip control chars; cap field lengths |
| Generated scripts in package | Never execute; static validation only; mark `scripts/` as inert until approved |
| Dependency resolver suggesting installs | Plans only, explicit approval, no auto-run, disclose cost |
| Vault package path traversal | Reuse `vault.resolve` per file; reject `..`, absolute paths, symlinks |
| Provenance tampering | Hash inputs (`content_hash`) and package files (`sha256`) |
| Overwriting published skills | 409 by default; overwrite requires explicit body flag; optional version suffix |
| Prompt-injected "facts" | Evidence labels + confidence; replication test must not reuse source content |
